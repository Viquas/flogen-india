1. `getProjectClaimAndRequests(projectId: string)` server action:
   - Purpose: Called from the editor when a project is loaded, to check if it's a purchased project and fetch its requests
   - Queries `claims` table for a claim with `.eq('project_id', projectId).in('status', ['paid', 'customizing', 'completed']).limit(1).single()`
   - If no claim found, returns `{ isPurchased: false }`
   - If claim found, fetches all `client_requests` for that project_id, ordered by created_at desc
   - Returns `{ isPurchased: true, claimId: string, clientName: string, businessName: string, requests: ClientRequest[] }`
   - Extract businessName from the project's business_data (query project alongside claim)

2. `updateRequestStatus(requestId: string, newStatus: 'in_progress' | 'completed', adminNotes?: string)` server action:
   - Uses `createAdminClient()` to bypass RLS
   - Builds update payload: `{ status: newStatus, updated_at: new Date().toISOString() }`
   - If `newStatus === 'completed'` and `adminNotes` is provided (non-empty string), add `admin_notes: adminNotes` to payload
   - Updates the single request by id
   - Calls `revalidatePath('/dashboard/clients')` to refresh list counts
   - Returns `{ success: boolean, error?: string }`

3. `redeployProject(projectId: string, generatedCode: string)` server action:
   - Purpose: Save code, version bump, revision snapshot, auto-complete in-progress requests, set status to 'deployed'
   - Step 1: Call `updateProjectWithCode(projectId, generatedCode)` from `@/lib/ai/project-persistence` -- this handles snapshot + version increment + code save. Import the function directly (it's already re-exported from `@/lib/ai/generator` but the direct import from `project-persistence.ts` is cleaner).
   - CRITICAL per Pitfall 1 in RESEARCH.md: `updateProjectWithCode` hardcodes `status: 'review'`. Immediately after, update the project status to `'deployed'`:
     ```typescript
     await supabase.from('projects').update({ status: 'deployed', updated_at: new Date().toISOString() }).eq('id', projectId)
     ```
   - Step 2: Auto-complete in-progress requests (Claude's discretion -- implementing auto-complete per RESEARCH.md recommendation):
     ```typescript
     await supabase.from('client_requests').update({ status: 'completed', admin_notes: 'Completed via redeploy', updated_at: new Date().toISOString() }).eq('project_id', projectId).eq('status', 'in_progress')
     ```
   - Step 3: Revalidate paths: `/dashboard/clients`, `/editor`
   - Returns `{ success: boolean, error?: string }`
   - Note: The `generatedCode` parameter comes from the editor's current state -- the editor already holds the latest code in its `generatedCode` useState.
