1. Create `app/(admin)/dashboard/clients/actions.ts` with `"use server"` directive:
   - `getClients(filters?: { status?: string; plan?: string })` server action:
     - Uses `createAdminClient()` from `@/lib/supabase/admin`
     - Queries `claims` table with `.in('status', ['paid', 'customizing', 'completed'])` (CRITICAL: use all three statuses per Pitfall 6 in RESEARCH.md)
     - Joins `projects!inner(id, business_data, slug, version, updated_at)` for business name extraction
     - Fetches `client_requests` for all matching project_ids in a separate query (Supabase does NOT support COUNT in embedded selects -- Pitfall 3)
     - Builds a Map of projectId -> requests, counts open requests client-side: `reqs.filter(r => r.status !== 'completed').length`
     - Derives fulfillment status per client (Claude's discretion, recommend): "Pending Customization" = has pending requests + no in_progress; "In Progress" = has at least one in_progress request; "Delivered" = all requests completed or no requests
     - Returns `{ success: boolean, data?: ClientListItem[], error?: string }` where `ClientListItem` has: claimId, projectId, businessName (from business_data.businessName), clientName, clientEmail, plan, paidAt, slug, openRequestCount, totalRequestCount, fulfillmentStatus, projectVersion, projectUpdatedAt
     - Applies plan filter in the Supabase query (`.eq('plan', filters.plan)` if provided)
     - Applies status filter client-side against derived fulfillmentStatus
     - Orders by `paid_at` descending (newest first)
   - `getClientDetail(claimId: string)` server action:
     - Fetches single claim with same join pattern
     - Also fetches ALL client_requests for that project_id, ordered by created_at descending
     - Returns `{ success: boolean, data?: { client: ClientListItem, requests: ClientRequest[] }, error?: string }`
     - ClientRequest type mirrors the DB row type from database.ts

   - Header area: "Clients" title + count badge + two DropdownMenu filters (Status, Plan) using shadcn DropdownMenu pattern from history-sidebar
   - Card grid layout: responsive grid (1 col mobile, 2 cols md, 3 cols lg) using `grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-4`

     - Open request count: red badge if > 0, gray if 0
     - Fulfillment status badge: color-coded (amber for Pending Customization, blue for In Progress, green for Delivered)
   - Each card is a Next.js Link to `/dashboard/clients/${claimId}`
   - Empty state: "No purchased clients yet" with a subtle illustration or icon
