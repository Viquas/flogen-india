**proxy.ts (project root, same level as app/):**

Create the Next.js 16 proxy entry point. CRITICAL: The exported function MUST be named `proxy` (not `middleware` -- that was the Next.js 14/15 convention). The matcher config uses a strict whitelist -- ONLY `/portal/:path*` and `/auth/callback`. Nothing else.

```
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'
import { updateSession } from '@/lib/supabase/proxy'

export async function proxy(request: NextRequest) {
  return await updateSession(request)
}

export const config = {
  matcher: [
    '/portal/:path*',
    '/auth/callback',
  ],
}
```

This is the complete file. Do NOT add a broad catch-all matcher. Do NOT add negative lookahead patterns. The whitelist approach per user decision means new routes are unaffected by default.

**lib/supabase/proxy.ts:**

Create the updateSession utility following the exact pattern from the research document (Pattern 2). Key implementation details:

1. Start with `let response = NextResponse.next({ request: { headers: request.headers } })`
2. Create Supabase server client using `createServerClient` from `@supabase/ssr` with ANON key (not service role)
3. Cookie bridge uses `request.cookies.getAll()` for reads and the reassignment pattern for writes: inside `setAll`, first set cookies on request, then `response = NextResponse.next({ request })`, then set cookies on the new response with options
4. Call `supabase.auth.getUser()` (not getSession -- locked decision from research) to refresh the session
5. Check if the path starts with `/portal` AND is NOT `/portal/login` AND user is null -- if so, redirect to `/portal/login`
6. If user IS authenticated and on `/portal/login`, redirect to `/portal` (they're already logged in)
7. For `/auth/callback` route, just pass through (session refresh is sufficient)
8. Return response

Import `Database` type from `@/types/database` and type the client as `createServerClient<Database>` to match the existing codebase pattern.

Do NOT use `getSession()` -- Supabase warns against this in server contexts. Use `getUser()` per the established pattern in lib/supabase/server.ts.

**lib/supabase/portal.ts:**

Create the portal-specific Supabase client per the locked two-client pattern decision. This is the anon-key client used for identity verification via `auth.getUser()` in portal server components and API routes.

Follow the exact same cookie bridge pattern as the existing `lib/supabase/server.ts` (which uses `cookies()` from `next/headers` with `getAll`/`setAll`). The only difference from server.ts is the function name: `createPortalClient` (not `createClient`).

The function should be async (awaits `cookies()`), import `Database` from `@/types/database`, and use `NEXT_PUBLIC_SUPABASE_URL` + `NEXT_PUBLIC_SUPABASE_ANON_KEY`. The `setAll` catch block should include a comment noting that the proxy handles session refresh, matching the pattern in server.ts.

Export as a named async function: `export async function createPortalClient()`.

**app/auth/callback/route.ts:**

Create a GET route handler at `/auth/callback` for Supabase auth email confirmations and password reset links. This handles the PKCE code exchange flow:

1. Extract the `code` query parameter from the request URL
2. Extract the `next` query parameter (default to `/portal`)
3. If `code` exists, create a Supabase server client using `createServerClient` from `@supabase/ssr` with the same cookie bridge pattern (using `request.cookies` for reads and `response.cookies` for writes -- similar to proxy context since this is a route handler, NOT a server component)
4. Call `supabase.auth.exchangeCodeForSession(code)` to convert the auth code into a session
5. Redirect to the `next` URL (always `/portal` per locked decision -- no redirect-back logic)
6. If no code parameter, redirect to `/portal/login`

IMPORTANT: The cookie bridge in route handlers uses `request.cookies` and the Response (not `cookies()` from next/headers). Follow the same pattern as the proxy updateSession but adapted for a route handler context. Use NextResponse.redirect for the redirect.

Add `export const dynamic = 'force-dynamic'` to prevent caching.
