**confirmed-actions.ts -- new file with 'use server' directive:**

**Action 1: `createAccountAndLogin(input: { claimId: string; email: string; password: string })`**
Returns: `Promise<{ success: true } | { success: false; error: string; existingUser?: boolean }>`

Implementation:
1. Create admin client via `createAdminClient()`
2. Verify email matches the claim's payment email:
   - Query claims table: `select('id, client_email, auth_user_id').eq('id', input.claimId).in('status', ['paid', 'customizing', 'completed']).single()`
   - If not found, return `{ success: false, error: 'Claim not found or not paid' }`
   - If `claim.client_email !== input.email`, return `{ success: false, error: 'Email does not match payment email' }`
3. Check if account already linked:
   - If `claim.auth_user_id` is not null, return `{ success: false, error: 'Account already exists for this claim', existingUser: true }`
4. Attempt to create auth user (handles duplicate detection):
   - Call `supabase.auth.admin.createUser({ email: input.email, password: input.password, email_confirm: true, user_metadata: { source: 'claim', claim_id: input.claimId } })`
   - If error message contains "already registered" or "already been registered": return `{ success: false, error: 'An account with this email already exists. Please log in instead.', existingUser: true }`
   - If other error: return `{ success: false, error: error.message }`
5. Link auth user to claim:
   - `supabase.from('claims').update({ auth_user_id: newUser.user.id }).eq('id', claim.id)`
6. Auto-login via SSR client with cookie bridge:
   - Import `cookies` from `next/headers`
   - Import `createServerClient` from `@supabase/ssr`
   - Create a one-off SSR client with the cookies() bridge (same pattern as createPortalClient in lib/supabase/portal.ts)
   - Call `portalClient.auth.signInWithPassword({ email: input.email, password: input.password })`
   - If sign-in error: log it but still return success (user was created, they can log in manually)
7. Return `{ success: true }`

**Action 2: `loginExistingAccount(input: { email: string; password: string })`**
Returns: `Promise<{ success: true } | { success: false; error: string }>`

Implementation:
1. Create SSR client with cookie bridge (same pattern as above)
2. Call `signInWithPassword({ email: input.email, password: input.password })`
3. If error: return `{ success: false, error: 'Invalid email or password' }`
4. Return `{ success: true }`

**Important anti-patterns to avoid:**
- Do NOT use `auth.admin.listUsers()` to check for existing users -- it fetches all users. Use the createUser-then-catch approach instead.
- Do NOT expose the admin client to any client component
- Do NOT import this file without 'use server' directive
