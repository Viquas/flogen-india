<objective>
Build the autopilot UI: a one-button trigger integrated into the existing discovery panel, a real-time progress display that polls every 3 seconds during execution, and a batch report that surfaces failures grouped by error classification.

Purpose: Without this UI, the autopilot backend has no way to be triggered or monitored. This plan gives the user a single button to start the pipeline and visual feedback throughout execution.
Output: 3 new client components (AutopilotButton, BatchProgress, BatchReport) wired into the existing discovery search panel.
</objective>

**1. Create webgen/components/dashboard/autopilot-button.tsx:**

"use client" component. Props: `{ query: string; location: string; industry: string; entries: number; templateId?: string }` -- these come from the parent discovery-search form state.

Behavior:
- Two additional config fields rendered inline: a checkbox "Auto-fix errors" (default: true) and a number input "Quality threshold" (default: 50, range 0-100, shown only when auto-fix is checked)
- On click: calls `runAutopilot({ query: props.query || props.industry, location: props.location, industry: props.industry, entries: props.entries, templateId: props.templateId, autoFixEnabled, qualityThreshold })`
- On success: stores the returned `runId` in state, which triggers rendering the `<BatchProgress>` component
- Before starting: calls `getActiveAutopilotRuns()` -- if any active runs exist, shows an amber warning badge "1 run active" but still allows starting a new one
- Button disabled when query/industry is empty (same logic as existing "Generate Sites" button)
- Uses Lucide `Rocket` icon. Styling: `bg-orange-600 hover:bg-orange-700 text-white` to differentiate from the purple "Generate Sites" button
- When a run is active (runId set), the button shows "Running..." with a Loader2 spinner and is disabled

**2. Create webgen/components/dashboard/batch-progress.tsx:**

"use client" component. Props: `{ runId: string; onComplete: () => void }`.

Behavior:
- On mount and every 3 seconds, calls `getAutopilotProgress(runId)` server action
- Displays:
  - **Stage indicator**: A horizontal stepper showing stages (Discover -> Enqueue -> Generate -> Fix -> Score -> Done) with the current stage highlighted. Use small colored dots/badges: gray for future, blue/pulsing for current, green for past, red for failed.
  - **Progress counts**: "X of Y generated, Z failed" as a summary line
  - **Progress bar**: Determinate progress bar (generated + failed) / total, colored green for generated portion and red for failed portion. Use Tailwind bg-green-500 / bg-red-500.
  - **Duration**: Elapsed time since startedAt, formatted with date-fns `formatDistanceToNow`
  - **Average quality**: When available (scoring stage+), show avg_quality_score as a badge
- When `isComplete` is true: stop polling, show final state (Completed with green check or Failed with red X and error message), call `onComplete()`
- If stage is 'failed': show the error_message from the response in a red alert box
- Wrap in a card with subtle orange border to match the autopilot branding

**3. Create webgen/components/dashboard/batch-report.tsx:**

"use client" component. Props: `{ batchId: string }`.

Behavior:
- On mount: fetches all projects for the batch via supabase query (projects WHERE batch_id = batchId)
- Groups projects into 4 categories:
  - `success`: status = 'review' or 'approved' AND quality_score >= 50 (or whatever makes sense)
  - `fixed`: status = 'review' AND had previous error (we can detect this if error_type is set but status is no longer 'error')
  - `needs_review`: status = 'review' AND quality_score < 50
  - `failed`: status = 'error'
- Displays category counts as colored badges at the top: green for success, blue for fixed, yellow for needs_review, red for failed
- Failed projects section: grouped by `error_type` (using ErrorType enum labels). For each error type group, show:
  - Error type label with count (e.g., "Syntax Error (3)")
  - Expandable list of project names (business_data.businessName) with their error_details truncated to 100 chars
  - Each project row has a link to the editor page (`/editor?id={projectId}`)
- If no failed projects: show a green "All projects generated successfully" message
- Uses a collapsible/accordion pattern (simple useState toggle, no radix dependency needed)
