**1. Create webgen/lib/export/static-export.ts:**

This module takes a project's generated code and business data and produces an export-ready HTML file. Per pitfall P5, we must NOT use server-side rendering -- we export the full client-rendered bundle (same as preview) to preserve React interactivity (navigation toggles, scroll animations, form handlers, modals).

```typescript
import { constructHtmlBoilerplate } from '@/lib/utils/html-boilerplate'

export interface ExportOptions {
  businessName: string
  industry?: string
  description?: string
}

export function buildStaticExport(generatedCode: string, options: ExportOptions): string
```

Implementation:
- Call `constructHtmlBoilerplate(generatedCode)` to get the base HTML
- Modify the HTML to enhance it for standalone use:
  1. **Replace the `<title>`**: Change `<title>Preview</title>` to `<title>${escapeHtml(options.businessName)}${options.industry ? ' | ' + escapeHtml(options.industry) : ''}</title>`
  2. **Add meta description**: Insert `<meta name="description" content="${escapeHtml(options.description || options.businessName + ' website')}">` after the viewport meta tag
  3. **Add Open Graph tags**: Insert after meta description:
     - `<meta property="og:title" content="${escapeHtml(options.businessName)}">`
     - `<meta property="og:description" content="${escapeHtml(options.description || '')}">`
     - `<meta property="og:type" content="website">`
  4. **Remove the parent postMessage calls**: The exported file is standalone, not inside an iframe. Replace `window.parent.postMessage` calls with comments or remove them. Use string replace: `.replace(/try\s*\{[^}]*window\.parent\.postMessage[^}]*\}\s*catch\s*\([^)]*\)\s*\{[^}]*\}/g, '/* standalone mode */')`
  5. **Add a generated-by comment**: Insert `<!-- Generated by WebGen -->` after `<!DOCTYPE html>`

- Add an `escapeHtml` helper function that escapes `<`, `>`, `&`, `"`, `'` for safe HTML attribute embedding.

- Return the modified HTML string.

**2. Create webgen/app/api/export/[projectId]/route.ts:**

A GET endpoint that fetches the project, builds the export, and returns it as a downloadable file.

```typescript
import { NextRequest, NextResponse } from 'next/server'
import { createAdminClient } from '@/lib/supabase/admin'
import { buildStaticExport } from '@/lib/export/static-export'

export async function GET(
  request: NextRequest,
  { params }: { params: Promise<{ projectId: string }> }
) {
  const { projectId } = await params
  const supabase = createAdminClient()

  // 1. Fetch project
  const { data: project, error } = await supabase
    .from('projects')
    .select('id, business_data, generated_code')
    .eq('id', projectId)
    .single()

  if (error || !project) {
    return NextResponse.json({ error: 'Project not found' }, { status: 404 })
  }

  if (!project.generated_code) {
    return NextResponse.json({ error: 'No generated code to export' }, { status: 400 })
  }

  // 2. Extract business data
  const businessData = project.business_data as any
  const businessName = businessData?.businessName || businessData?.business_name || 'website'

  // 3. Build export
  const html = buildStaticExport(project.generated_code, {
    businessName,
    industry: businessData?.industry,
    description: businessData?.description,
  })

  // 4. Generate safe filename
  const safeFilename = businessName
    .toLowerCase()
    .replace(/[^a-z0-9]+/g, '-')
    .replace(/^-|-$/g, '')
    .substring(0, 50)
    || 'website'

  // 5. Return as downloadable HTML file
  return new NextResponse(html, {
    status: 200,
    headers: {
      'Content-Type': 'text/html; charset=utf-8',
      'Content-Disposition': `attachment; filename="${safeFilename}.html"`,
    },
  })
}
```

NOTE: Next.js 16 App Router uses `params` as a Promise in dynamic route handlers. The destructuring `const { projectId } = await params` is the correct pattern.

**1. Create webgen/components/editor/export-button.tsx:**

"use client" component. A download button that triggers the export API route.

Props:
```typescript
interface ExportButtonProps {
  projectId: string
  disabled?: boolean  // disabled when no generated code
}
```

Behavior:
- On click: fetch `/api/export/${projectId}` and trigger a browser download
- Implementation pattern (client-side file download from API):
  ```typescript
  const handleExport = async () => {
    setIsExporting(true)
    try {
      const response = await fetch(`/api/export/${projectId}`)
      if (!response.ok) {
        const err = await response.json()
        throw new Error(err.error || 'Export failed')
      }
      // Extract filename from Content-Disposition header
      const disposition = response.headers.get('Content-Disposition')
      const filenameMatch = disposition?.match(/filename="?([^"]+)"?/)
      const filename = filenameMatch?.[1] || 'website.html'

      const blob = await response.blob()
      const url = URL.createObjectURL(blob)
      const a = document.createElement('a')
      a.href = url
      a.download = filename
      document.body.appendChild(a)
      a.click()
      document.body.removeChild(a)
      URL.revokeObjectURL(url)
    } catch (err) {
      console.error('Export failed:', err)
      // Could add toast notification here
    } finally {
      setIsExporting(false)
    }
  }
  ```
- State: `isExporting` boolean for loading state
- Button styling: Match existing editor toolbar buttons. Use `Button` from shadcn/ui with `variant="outline"` and `size="sm"`. Icon: `Download` from lucide-react.
- When exporting: show `Loader2` spinner icon. When done: briefly show checkmark (optional, but nice)
- Disabled when `disabled` prop is true or `isExporting` is true
