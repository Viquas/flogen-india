Build a client-side prefetch cache for project data: when the user is reviewing one project, the next 3 projects in the list are prefetched in the background. Navigating to a prefetched project loads instantly from cache. The cache uses LRU eviction to stay bounded.

Output: `usePrefetchCache` hook with LRU cache, integration into the editor page and project grid.

**Create webgen/hooks/use-prefetch-cache.ts:**

A React hook that manages an in-memory LRU cache of project data and provides methods for prefetching and retrieval.

```typescript
interface CachedProject {
  id: string
  business_data: any
  generated_code: string | null
  status: string
  version: number
  [key: string]: any  // other project fields
  cachedAt: number     // timestamp for staleness check
}

interface PrefetchCacheReturn {
  // Get a cached project, or null if not cached
  getCached: (projectId: string) => CachedProject | null

  // Prefetch the next N projects from a given project list
  // This runs in the background (non-blocking)
  prefetchNext: (currentProjectId: string, projectIds: string[]) => void

  // Manually add a project to the cache (e.g., when loaded via normal flow)
  addToCache: (project: CachedProject) => void

  // Clear the entire cache
  clearCache: () => void

  // Number of cached items (for debugging)
  cacheSize: number
}

export function usePrefetchCache(maxSize: number = 5): PrefetchCacheReturn
```

Implementation:

**LRU Cache data structure** (use a `useRef` to persist across renders without causing re-renders):
```typescript
const cacheRef = useRef<Map<string, CachedProject>>(new Map())
const [cacheVersion, setCacheVersion] = useState(0) // trigger re-render when cache size changes for cacheSize
```

Use a `Map` as the backing store. `Map` preserves insertion order, which makes LRU implementation simple:
- On `get`: delete the entry and re-insert it (moves to end = most recently used)
- On `set`: if size exceeds `maxSize`, delete the first (oldest) entry

**getCached(projectId)**:
- If the cache has the entry, move it to the end (LRU touch) and return it
- Check staleness: if `cachedAt` is older than 5 minutes, evict and return null
- If not found, return null

**addToCache(project)**:
- Add/update the entry with `cachedAt: Date.now()`
- If cache size exceeds maxSize, evict the least recently used entry (first in Map)

**prefetchNext(currentProjectId, projectIds)**:
- Find currentProjectId in the projectIds array
- Take the next 3 IDs after the current one
- For each ID not already in cache: schedule a fetch using `requestIdleCallback` (with `setTimeout` fallback for browsers that don't support it)
- The fetch calls `getProjectById(id)` (imported from actions) -- wrapped in a try/catch so failures are silent (prefetch is best-effort)
- On success, call `addToCache` with the fetched data
- Use an in-flight `Set<string>` (useRef) to avoid duplicate concurrent fetches for the same project

**requestIdleCallback wrapper:**
```typescript
const scheduleIdle = (fn: () => void) => {
  if (typeof requestIdleCallback !== 'undefined') {
    requestIdleCallback(fn, { timeout: 2000 })
  } else {
    setTimeout(fn, 100)
  }
}
```

**clearCache()**: Clear the Map and the in-flight Set.

**cacheSize**: Return `cacheRef.current.size`.

**Important per P12**: Prefetching must never compete with active work. Use requestIdleCallback, limit to 3 prefetches, and never prefetch while the user is actively loading a project (check a `useRef<boolean>` for active loading state).

const loadProject = async (id: string) => {
    console.log('[Editor] Loading project:', id)

    // Check prefetch cache first
    const cached = getCached(id)
    if (cached) {
        console.log('[Editor] Loaded from prefetch cache:', id)
        applyProjectData(cached)
        // Still trigger prefetch for next projects
        triggerPrefetch(id)
        return
    }

    // Existing getProjectById flow...
    setIsJsonLoading(true)
    try {
        const result = await getProjectById(id)
        if (result.success && result.data) {
            const project = result.data
            applyProjectData(project)
            // Add to cache for potential back-navigation
            addToCache({ ...project, cachedAt: Date.now() })
            // Trigger prefetch for next projects
            triggerPrefetch(id)
        } else {
            setError(result.error || "Failed to load project")
        }
    } catch (e) {
        setError("Critical error loading project")
    }
    setIsJsonLoading(false)
}
```

Add at the bottom of the `filteredProjects` useMemo effect:

useEffect(() => {
    // Store project order for editor prefetching
    const ids = filteredProjects.map(p => p.id)
    try {
        localStorage.setItem('webgen-project-order', JSON.stringify(ids))
    } catch (e) {
        // localStorage may be unavailable
    }
}, [filteredProjects])
```

Then in the editor, when triggering prefetch, read from localStorage as a fallback:
```typescript
const triggerPrefetch = (currentId: string) => {
    let projectIds = projectHistory.map(p => p.id)
    // Try to use the dashboard's filtered order for more accurate prefetching
    try {
        const stored = localStorage.getItem('webgen-project-order')
        if (stored) {
            const parsed = JSON.parse(stored)
            if (Array.isArray(parsed) && parsed.length > 0) {
                projectIds = parsed
            }
        }
    } catch (e) {}
    prefetchNext(currentId, projectIds)
}
```

This is a lightweight coordination mechanism. The dashboard writes the list order; the editor reads it for prefetch ordering.
