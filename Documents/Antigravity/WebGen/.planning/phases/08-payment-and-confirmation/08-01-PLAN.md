Add the following NEW exports after the existing code:

```typescript
export const GST_RATE = 0.18 // 18% GST for India

/** Calculate GST amount in paise. Returns 0 for non-INR currencies. */
export function calculateGST(planPaise: number, currency: Currency): number {
    if (currency !== 'INR') return 0
    return Math.round(planPaise * GST_RATE)
}

/** GST display strings for INR (e.g. '900', '1,800'). Returns null for USD. */
export const GST_DISPLAY = {
    standard: { INR: '900', USD: null },
    pro:      { INR: '1,800', USD: null },
} as const

/**
 * Calculate total order amount in paise/cents.
 * INR: plan + hosting + GST(18% on plan)
 * USD: plan + hosting
 * This is the amount sent to Razorpay.
 */
export function calculateTotalPaise(plan: PlanType, currency: Currency): number {
    const planAmount = PRICING[plan][currency]
    const hostingAmount = HOSTING_PRICING[currency].amount
    const gst = calculateGST(planAmount, currency)
    return planAmount + hostingAmount + gst
}

/** Display-friendly total for summary. */
export function getDisplayTotal(plan: PlanType, currency: Currency): string {
    const total = calculateTotalPaise(plan, currency)
    // Convert from paise/cents to display: divide by 100, format with commas
    const amount = total / 100
    return amount.toLocaleString('en-IN', { maximumFractionDigits: 0 })
}
```

Verify the math:
- Standard INR: 499900 (plan) + 49900 (hosting) + 89982 (GST = 499900 * 0.18) = 639782 paise = Rs 6,397.82 — but GST should be on plan only. Math.round(499900 * 0.18) = 89982. Total = 639782 paise.
- Standard USD: 49900 + 1000 = 50900 cents = $509
- Pro INR: 999900 + 49900 + Math.round(999900 * 0.18) = 999900 + 49900 + 179982 = 1229782 paise
- Pro USD: 129900 + 1000 = 130900 cents = $1,309

Extend the existing `claim-actions.ts` file (which already has `submitExpiredClaimRequest`). Add a new `createRazorpayOrder` server action below the existing function.

**The server action must:**

1. Accept parameters: `projectId: string`, `plan: PlanType`, `currency: Currency`, `domainOption: string`, `domainValue: string`
2. Validate inputs with Zod:
   ```typescript
   const orderSchema = z.object({
       projectId: z.string().uuid(),
       plan: z.enum(['standard', 'pro']),
       currency: z.enum(['INR', 'USD']),
       domainOption: z.enum(['subdomain', 'existing', 'new']),
       domainValue: z.string().max(253).optional().default(''),
   })
   ```
3. **Idempotency check** — query `claims` table for existing claim with same `project_id` and status IN ('pending', 'order_created'). If found AND has a `razorpay_order_id`, return that existing order. This prevents double-charge from double-click (Pitfall 3 from research).
4. **Create claim record** — insert into `claims` table:
   - `project_id`, `plan`, `currency`, `domain_option`, `domain_value`
   - `amount_paise`: use `calculateTotalPaise(plan, currency)` from updated claim-pricing.ts
   - `status`: 'pending'
   - `expires_at`: `new Date(Date.now() + 5 * 24 * 60 * 60 * 1000).toISOString()`
5. **Create Razorpay order** — call `razorpay.orders.create()`:
   - `amount`: same `calculateTotalPaise(plan, currency)` value
   - `currency`: the currency string ('INR' or 'USD')
   - `receipt`: claim.id (the UUID)
   - `notes`: `{ claimId: claim.id, projectId, plan }`
6. **Update claim** with `razorpay_order_id` from Razorpay response and set status to 'order_created'
7. Return `{ success: true, orderId: order.id, claimId: claim.id }` on success, `{ success: false, error: string }` on failure

**Error handling:** Wrap the Razorpay API call in try/catch. If order creation fails after claim insert, still return failure (the claim record with status 'pending' will be reused on retry due to idempotency check).

Add these imports to the top of the file:

