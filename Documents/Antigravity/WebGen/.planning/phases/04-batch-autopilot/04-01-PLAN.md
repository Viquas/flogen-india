-- Phase 4: Batch Autopilot
CREATE TABLE IF NOT EXISTS batch_runs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    batch_id UUID REFERENCES batches(id) ON DELETE SET NULL,
    current_stage TEXT NOT NULL DEFAULT 'pending'
        CHECK (current_stage IN ('pending', 'discovering', 'enqueueing', 'generating', 'fixing', 'scoring', 'completed', 'failed')),
    config JSONB NOT NULL,

    started_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    completed_at TIMESTAMPTZ DEFAULT NULL,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_batch_runs_stage ON batch_runs(current_stage) WHERE current_stage NOT IN ('completed', 'failed');
CREATE INDEX IF NOT EXISTS idx_batch_runs_batch ON batch_runs(batch_id);

ALTER TABLE batch_runs ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Allow all access to batch_runs" ON batch_runs FOR ALL USING (true) WITH CHECK (true);

**1. Create webgen/lib/autopilot.ts** -- the core state machine orchestrator.

Import types from `autopilot-types.ts`, `createAdminClient` from `@/lib/supabase/admin`, `discoverBusinesses` from `@/lib/discovery`, `generationQueue` from `@/lib/queue`, `fixWebsiteErrors` from `@/app/dashboard/actions`.

Implement `runAutopilotPipeline(runId: string): Promise<void>` with this structure:

```typescript
export async function runAutopilotPipeline(runId: string): Promise<void> {
  // 1. Load batch_run row
  // 2. Stage handler map: pending->discover, discovering->discover, enqueueing->enqueue, generating->generate, fixing->fix, scoring->score
  // 3. While loop: read current_stage, call handler, re-read stage, loop until completed/failed
  // 4. Wrap each handler call in try/catch -- on error, call markFailed(runId, message)
}
```

**Stage handlers (all must be idempotent):**

`executeDiscoverStage(run)`:
- If `run.batch_id` is set AND projects exist for that batch -> skip, advance to 'enqueueing'
- Otherwise: call `discoverBusinesses(run.config)`
- Update batch_run: set batch_id, update progress.total_projects, advance to 'enqueueing'

`executeEnqueueStage(run)`:
- Query projects WHERE batch_id = run.batch_id AND status = 'queued' that have NO queue_job (left join queue_jobs on project_id, where queue_jobs.id IS NULL -- OR simpler: just call addBatch which has duplicate key handling built in)
- Get all project IDs for the batch, call `generationQueue.addBatch(projectIds, undefined, run.config.templateId)`
- Advance to 'generating'

`executeGenerateStage(run)`:
- Poll loop: every 5 seconds, count queue_jobs by status for projects in this batch
- When all queue_jobs are completed OR failed (none pending/processing), advance to 'fixing'
- Timeout: `Math.min(Math.max(run.config.entries * 120, 300), 3600) * 1000` ms
- Every poll cycle, check for stuck processing jobs (started_at > 5 min ago) -- reset them to 'pending' status
- Update batch_run.progress with current counts on each poll
- On timeout: force-fail remaining pending/processing queue_jobs, advance to 'fixing'

`executeFixStage(run)`:
- If `!run.config.autoFixEnabled`, skip to 'scoring'
- Query projects WHERE batch_id = run.batch_id AND (status = 'error' OR (status = 'review' AND quality_score IS NOT NULL AND quality_score < run.config.qualityThreshold))
- Run fixes concurrently (3 at a time, matching existing autoFixAllErrors pattern) using Promise.allSettled and the existing `fixWebsiteErrors(projectId)` function
- Update batch_run.progress.fixed count
- Advance to 'scoring'

`executeScoringStage(run)`:
- Quality scoring already runs automatically in the generator pipeline (fire-and-forget hook)
- This stage just aggregates final results: query all projects for batch, compute avg_quality_score, count by status
- Update batch_run.progress with final counts
- Set current_stage = 'completed', set completed_at

**Helper functions:**
- `advanceStage(runId, nextStage)`: UPDATE batch_runs SET current_stage, updated_at
- `markFailed(runId, errorMessage)`: UPDATE batch_runs SET current_stage='failed', error_message, completed_at, updated_at
- `updateProgress(runId, progress)`: UPDATE batch_runs SET progress, updated_at

**2. Add server actions to webgen/app/dashboard/actions.ts:**

Add three new exported server actions at the bottom of the file:

`runAutopilot(config: BatchRunConfig)`:
- Create a new batch_run row with config, current_stage='pending', empty progress
- Call `runAutopilotPipeline(run.id)` as a fire-and-forget (but with .catch that calls markFailed)
- Return `{ success: true, runId: run.id }`

`resumeAutopilot(runId: string)`:
- Read the batch_run row
- If current_stage is 'completed' or 'failed', return error "Run already finished"
- Call `runAutopilotPipeline(runId)` fire-and-forget with .catch
- Return `{ success: true, runId }`

`getAutopilotProgress(runId: string)`:
- Read batch_run row (current_stage, batch_id, config, progress, error_message, started_at, completed_at)
- If batch_id exists: aggregate project statuses for this batch (total, generated count where status in review/approved, error count, generating count where status in generating/queued)
- Compute avg quality score from projects with non-null quality_score
- Return `{ stage, progress: counts, config, errorMessage, startedAt, completedAt, isComplete: stage === 'completed' || stage === 'failed' }`

Also add `getActiveAutopilotRuns()` to check for in-progress runs (for the UI warning):
- Query batch_runs WHERE current_stage NOT IN ('completed', 'failed'), order by started_at desc
- Return array of { id, current_stage, started_at, config }
